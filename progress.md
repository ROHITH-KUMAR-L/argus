### Phase 2: Permission model and monotonic ratchet (2026-11-03)
- `crates/privilege-ratchet`:
  - `expansion_delta` / `is_subset` per permission class. Filesystem coverage is the union of ancestor grants, matching Landlock semantics. Syscalls compare by denied set; also network, tools, executables, shell and limits.
  - Deterministic `Engine` driven by explicit ops and `now`: epochs, transition history with reason codes and deltas, mixed transitions rejected whole.
  - Approvals are single-use, bound to the epoch and policy hash, and expire (default 900 s). Approval closes the epoch and opens a new one.
  - Arm semantics: P1 = full ratchet; B1 = static policy (`ARM_STATIC_POLICY`); B0 = ungated, `confinement: none`.
  - `evaluate_action` resolves workspace-relative paths, catalog executables, argv bounds, timeouts and symbolic test targets into a `WorkerRequest` dispatch.
- `policy-model`: strict `Action` / `Operation` / `WorkerRequest` types; `test_targets` catalog in the deployment config.
- `ratchetd` daemon:
  - decision and approval UDS sockets (`0600`, runtime dir `0700`), `SO_PEERCRED` uid check, request-id replay protection, 1 MiB frames, connection cap;
  - write-ahead, hash-chained, fsynced op log with a config-pinning header and a state-dir lock;
  - refuses to start on any corruption or config mismatch. The only `unsafe` code is isolated in `src/sys.rs`.
- `controller/rust_client.py`: `RatchetClient` (decision socket, has no approve method) and `ApprovalClient` (trusted CLI only). Policies are sent as raw JSON text so Rust sees duplicate keys.

**Tests / evidence:** `cargo test`: 58 passed.
- Engine: 21 tests (RAT-001…016, 020…023, arms, gate basics).
- RAT-024 property test: 1000 cases against an independent oracle; a measurement run showed 2129 accepted narrowings and 1307 rejected expansions, all consistent.
- Daemon: 9 tests over real sockets (RAT-017 race with 8 writers, 1 winner; RAT-018 restart; RAT-019 truncation/tamper/drop/empty/permissions; RAT-023 socket separation; replay; frame limit; config mismatch; double daemon).

### Phase 3: Structured audit and task state (2026-11-03)
- `controller/audit/events.py`: versioned `Event` model (strict). The enforcement layer is a separate field, so a policy-gate denial is never counted as a kernel denial. Published as `schemas/event.schema.json`.
- `controller/audit/writer.py`: trusted append-only JSONL store (dir `0700`, file `0600`). Every row is redacted, schema-validated, hash-chained and fsynced, and resuming requires a verified chain. A write or open failure raises `AuditUnavailable` (fail closed). `verify()` checks schema, sequence, chain and permissions.
- `controller/audit/redact.py`: exact known-secret redaction; patterns for OpenAI/Anthropic, AWS, GitHub, Slack, JWT, bearer tokens, private keys and `key=value` secrets; sensitive-key redaction for structured data; byte-bounded capture with an explicit truncation marker.
- `controller/audit/lifecycle.py`: `workflow.md` §4 state machine; illegal transitions raise; terminal events are emitted.
- `controller/audit/report.py`: lifecycle and policy-history reconstruction; metric aggregation by type, decision and enforcement layer.
- `controller/audit/bridge.py`: maps ratchetd results and errors onto audit events (used by the graph in Phase 9).

### Phase 4: Execution supervisor and process lifecycle (2026-11-03)
- `crates/process-supervisor`:
  - argv-only spawn with a cleared environment and its own process group;
  - rlimits (CPU soft < hard so SIGXCPU identifies the limit, AS, FSIZE, NOFILE, NPROC, core 0) and a fail-closed pre-exec confinement hook;
  - bounded stdout/stderr that keeps draining past the cap; wall deadline;
  - whole-tree cleanup: process group, then subreaper reaping of reparented descendants (daemons, `setsid`), and `kill(-1)` only as PID 1; rusage.
- `crates/execution-launcher` (`argus-worker`):
  - strict `WorkerRequest` check: version, ids, arm ↔ confinement consistency, re-hash and canonical re-validation of the embedded policy, workspace / executable / timeout checks for kernel-confined arms;
  - file operations (list, read, write, strict unified-diff `apply_patch`) run in a re-executed child with the same rlimits and confinement hook, use `O_NOFOLLOW`, and report errno-classified errors;
  - JSON `WorkerResult`.
- `crates/linux-confinement`: `plan` / `install` API, a **fail-closed stub** until Phases 6–7.
- `controller/workspace.py`: approved-file staging tar re-owned to UID 10001 (refuses symlinks and special files); two-pass export validator (absolute, `..`, symlink, hardlink, device, FIFO, unexpected or outside-root entries reject the whole export) with `O_EXCL | O_NOFOLLOW` extraction and SHA-256 artifacts.
- `controller/executor.py`: `Executor` protocol and `MockExecutor` (tests only).

### Phase 6: Landlock integration (2026-11-03)
- `linux-confinement::landlock_rules`:
  - `plan` (kernel ABI probe, handled ABI = min(kernel, 9), read-only → read + execute, read-write → all handled rights, net and scope at ABI ≥ 4 / ≥ 6, required-rights check);
  - `install` (hard-requirement ruleset, rule roots opened per component with `O_NOFOLLOW` so planted symlinks are fatal, file-only rights for non-directory roots, must be `FullyEnforced` with `no_new_privs`).
- `argus-worker`: B1/P1 actions now run under Landlock. The result reports the full plan (kernel and handled ABI, handled rights, rules, scoping) for AUD-005. File-op children are confined too.
- Image: synthetic canaries (`/opt/argus-canary/secret.txt`, `/etc/argus-canary.txt`) that DAC allows the worker to read, so only Landlock can deny them.
- Templates: `/dev/null` moved to read-write (needed by `subprocess.DEVNULL`).
- `check_config`: any seccomp/AppArmor override is now drift, not just `unconfined`.
- `docs/confinement.md`: sequence, attribution method, observed special-path behaviour, limits.
